### 2.2 SingleStore: $1,000 / $750 / $500 in gift cards of your choice
- **Build, deep integration:** make SingleStore the single store for (1) the **trusted knowledge base**: datasheets, vendor pages, compatibility notes and BOM docs as chunks with a `VECTOR(n)` column and a `FULLTEXT USING VERSION 2` index, using **hybrid search**; (2) `price_observations`, timestamped, with an "is this price stale or anomalous" SQL query; (3) `owned_parts` memory; (4) the hash-chained `audit_events` (JSON). The agent's retrieval tool is one hybrid SQL query. That is a deep integration, not a log table.
- **Can it replace Senso as the trusted knowledge base?** Technically yes. Hybrid search is documented on Helios as full-text `MATCH (TABLE t) AGAINST (...)` plus vector `<*>` (dot product), merged with weighted reciprocal rank fusion (0.7 / 0.3 in the docs example). The "Hybrid Search – Reranking Full-Text and Vector Search Results" page is linked in sources. Vector indexes are optional, since vector queries work without them. Full-text indexes need columnstore tables, which is the only table type on Shared, so nothing conflicts. Whether a *vector index* specifically works on Shared is **[unverified]**, but brute-force `<*>` over a few thousand chunks is fine. SingleStore has no built-in embedding model in the docs I read, so you supply embeddings (SIE Serverless, which also feeds the Superlinked prize).
- **Free Shared tier limits** (Shared Edition doc): **1 GB compressed** data; **AWS US-EAST-1 only**; fixed compute; **1 database**; **10 tables per database**; **no rowstore or reference tables**; 100 concurrent connections; 3 DB users; 10 pipelines; 10 stored procedures and UDFs combined; no automated backups; **no firewall, so the database is reachable from anywhere**; CREATE/DROP DATABASE disabled. The blog says idle free databases detach from compute, so the first query after idle may be slow. Card requirement: **not stated [unverified]**. One blog says the free tier is "public preview" and may need enabling **[may be stale]**.
- **Key tonight:** yes, very likely, via the self-serve portal at portal.singlestore.com **[card requirement unverified]**.
- **Minimal integration:** `pip install singlestoredb` (1.20.0 has `win_amd64` and `py3-none-any` wheels). **1.20.0 was published today, Nov 19.** If anything breaks, pin `singlestoredb<1.20`. Then `import singlestoredb as s2; conn = s2.connect('user:password@host:3306/db_name')`. DDL: `CREATE TABLE kb_chunks (id BIGINT, doc_id ..., body TEXT, emb VECTOR(1024), FULLTEXT USING VERSION 2 kb_ft (body))`. Query: `MATCH (TABLE kb_chunks) AGAINST ('body:servo*')` plus `emb <*> @q`. It is MySQL-wire compatible, so PyMySQL also works as a fallback.
- **Minutes:** 60–90 for KB, prices, owned parts and audit, including the hybrid query. 30–40 for prices and audit only.
- **Windows gotchas:** none in the client. Keep to 10 tables or fewer. The earlier plan of 7 tables fits. Columnstore unique keys are restricted (from general knowledge **[unverified]**), so enforce the hash chain in app code.
- **Judges (two SingleStore solutions engineers) want:** SingleStore doing real work in the agent loop: hybrid vector plus full-text retrieval, real-time analytics on price observations, JSON audit records, all in one database instead of separate stores. Show the SQL in the demo.

### 2.3 Airbyte: $1,000 / $500 / $250 Visa gift cards
- **The prize text asks for nothing specific.** The only pointer is the Context Layer docs link. The judge is a Senior Developer Advocate.
- **Correction to earlier research ("needs Airbyte Cloud plus a Snowflake/BigQuery warehouse"):** that is only half right.
  - **Context Layer, agent access** (direct reads of live source data through the Airbyte MCP): "You don't need a connection." For *sources*, the agent calls the connector's own API, so **no warehouse is needed**. Only SQL against *destinations* needs BigQuery or Snowflake.
  - **Context Layer, search** (semantic index): needs source *and* destination to be agent connectors, and backfills are limited to **Snowflake and BigQuery**. That is where the warehouse requirement comes from.
  - Both parts are **Airbyte Cloud only** (plan badges: Standard, Plus, Pro; not Core). The Context Layer is free up to 100,000 direct reads and searches per month per organization. Airbyte Cloud has a **14-day free trial with no credit card** (400 credits). Whether the trial includes Context Layer and MCP access is **[unverified]**. MCP endpoint: `https://mcp.airbyte.com/mcp` (add `?read-only=true` for read-only). Auth is OAuth, or **client credentials sent as `Client-Id` and `Client-Secret` headers** for headless Python, or a Bearer token that expires in 15 min. An org admin has to enable agent access per resource.
- **airbyte-agent-sdk runs locally with no Airbyte account, no warehouse and no paid plan.** The README says: "Run connectors locally with your own credentials in connector-specific auth configs; the SDK makes direct calls to each third-party API." Context-layer queries "aren't part of this SDK". `context_store_*` actions raise `NotImplementedError` locally.
  - PyPI `airbyte-agent-sdk` 0.1.403, pure-Python wheel, Python >= 3.11. `uv pip install airbyte-agent-sdk` (plain pip should work too).
  - The repo's `airbyte_agent_sdk/connectors/` has 57 connectors, **including `github`, `gmail` and `shopify`** (also google_drive, notion, slack, amazon_seller_partner, stripe, woocommerce).
  - Pattern: `from airbyte_agent_sdk.connectors.stripe import StripeConnector, StripeAuthConfig`, then `build_connector_tools(conn, framework="pydantic_ai"|"langchain"|"openai_agents"|"mcp")`, or call it directly with `await conn.execute(entity, action, params)`. There is no `anthropic` framework value, so with the raw Anthropic SDK wrap `execute` in your own tool and catch `AirbyteToolError`.
  - **GitHub connector:** auth is a **personal access token**, fine-grained or classic (from the standalone `airbyte-agent-github` README; the SDK's GitHub connector should match **[unverified]**). Entities include repositories, **file content, directory content**, issues, releases and commits. Read-only.
  - **Gmail connector:** needs a Google OAuth `client_id`, `client_secret` and `refresh_token` (a Google Cloud project, consent screen and test user). That is **30–60 min of setup** and risky at a hackathon. Do not depend on it.
  - **Shopify connector:** needs a **Shopify Admin API token** for a store *you* administer (customers, orders, products, inventory). It does **not** create carts on third-party Shopify stores, so it fits Build-to-Cart only if you read your own dev store's order history as owned parts.
  - The SDK depends on `segment-analytics-python`, so it may send usage telemetry. I could not find an opt-out variable **[unverified]**.
- **Build:** replace the plain-HTTP README fetch with the Airbyte **GitHub** agent connector. The agent reads the robot-arm repo's BOM file and directory tree (and maybe issues or releases for revision notes) as context. Every read is logged in the audit trail with entity, action and params. Stretch: an Airbyte Cloud trial with a GitHub source, agent access turned on, and the **Airbyte MCP** called from the agent, which matches the linked Context Layer docs and the judge's likely interest.
- **Key tonight:** yes. The local SDK only needs a GitHub PAT (2 min). The Cloud trial is self-serve with no card.
- **Minutes:** 30–45 for the local GitHub connector. +45–75 for the Cloud plus MCP path.
- **Windows gotchas:** pure Python. Python 3.11+ for the SDK, 3.13 if you use the standalone `airbyte-agent-*` packages. Prefer the SDK.
- **Judge wants [inference]:** Airbyte connectors as the agent's context source with typed tools, ideally through the Context Layer and MCP since that is the one doc they linked. Make it visible in the demo: "this BOM came from GitHub through Airbyte, read at 11:42."

8. **No multi-prize rule, no judging criteria and no grand prize** are published. The submit form is behind sign-in.
